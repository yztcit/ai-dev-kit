# 同一仓库多个检出的 .claude 配置

项目 `.claude`（agents / rules / skills / plans / settings.json）被 gitignore，所以它跟着**检出目录**走。
同一个仓库为了并行打开多个分支而建多个检出时，新检出根本没有 `.claude`，或者各存一份互相漂移
——实测：同一份 agent 文档在一个检出里 32KB、另一个里 16KB；某个 agent 只存在于其中一个检出。

`CLAUDE.md` 同理：远端仓库里没有它（各检出各存一份本地文件），实测两个检出一个登记了某领域 agent、
一个没有。所以**它也在对齐范围内**。

做法：不做软链、不额外开目录。各检出各留一份**真实**的 `.claude`，由 `sync.py` 在会话开始时对齐。

## 模型：主干权威，分支各自演进

不是「让所有检出一模一样」，而是「分支从主干取、改动留在分支、完工再合回主干」——和代码分支语义一致。

| 谁 | 行为 |
|---|---|
| 主干检出（**开发主分支**，默认找 develop / dev / main / master） | 权威。`sync.py` 只读它，**从不改它** |
| 其它检出 | 只要这个文件**自己没动过**，就跟随主干（新增 / 更新 / 删除都跟） |
| 其它检出 | 自己动过的文件 → **一律不动**，那是本分支的工作成果，等合并 |

「自己动过没有」靠每个检出的 `.claude/.sync-state.json`（上次与主干一致时的文件状态）判断。
**关键不变量：基线只记「上次与主干一致时的内容」**。分支改动后基线保持不动——一旦记成本地改动后的内容，
下次就会把它误判成「没动过」而被主干覆盖。

于是日常三种情形自动覆盖：

- **新建检出目录、开会话** → 本地从没有过 `.claude` → 全部跟随主干 = 从主干 fork 一份
- **分支没碰过文档、主干更新了** → 自动跟上（等价于 git 的快进）
- **分支改了文档** → 不动；主干后来也改了同一个文件 → 仍不动，等合并

## 什么时候用

- 用户说「这个项目多个目录，配置对不上」「帮我把 .claude 统一一下」「这个项目的 claude 配置我不想提交，但要共用」
- 用户新建了一个分支检出目录，想让配置跟主干一致
- **用户说「汇总 / 合并回主干 / 完工了」** → 见下面「合并回主干」

## 命令

```bash
python3 <AI-dev-kit>/shared-config/sync.py --status <检出目录>   # 只报告：主干是谁、哪些文件与主干不同
python3 <AI-dev-kit>/shared-config/sync.py <检出目录>            # 对齐（只动当前检出）
```

## 合并回主干（分支完工时）

**这一步脚本不做**——「分支的文档改动该不该进主干」需要人判断，自动化做不了。用户要求时按此做：

1. `sync.py --status <分支检出>` 列出本分支相对主干改过/独有的文件
2. 逐个 `diff` 分支版与主干版，读懂改了什么；判断是整体采用、还是只取其中一部分
3. 把结论写进**主干检出**的对应文件（主干是权威，脚本只读它、从不改它，所以这步必须手工写）
4. **把已采纳的文件在分支侧也更新成主干版**：`cp <主干检出>/<文件> <分支检出>/<文件>`
5. 到分支检出跑一次 `sync.py` → 分歧清零；你**没有**采纳的文件保持不动，继续算分歧（等下次再议）
6. 跟用户确认每个文件取了哪版、为什么

**第 4 步不能省。** 合并后主干往往是分支版**加上**主干原有的内容（比如两边各加了一节），
两边仍不相同——不做这一步，分支会一直挂着「本地已改（等合并回主干）」，看起来像没合并成。
只有「整体采用分支版」这一种情况才天然一致。

**不要拿分支版直接覆盖主干版**，也不要反向覆盖：两边可能各有价值。

其它检出不用管：主干更新后，那些**没动过**这些文件的检出会在各自下次会话开头自动跟上。

## 不要做的事

- **不要做软链**。踩过两次：整个 `.claude` 做成软链会让 health 巡检看不到该项目资产
  （`os.walk` 默认不跟随软链目录）；`rules/` 用目录软链会让 harness 的 instruction glob
  匹配不到，表现为「规则没加载」。这也是本方案不用软链的原因。
- **不要把分支的改动自动推给主干或其它分支**。那正是「完工后合并」这一步该由人决定的。
- **不要动 `.gitignore`**。老分支可能没忽略 `/.claude`，用 `.git/info/exclude` 兜底
  （本地文件，不会把 tracked 的 `.gitignore` 改成脏文件）。
- **不要把 `.sync-backup/` 当垃圾删**——那是找回被覆盖版本的唯一途径。

## 之后

新建分支检出目录后**不需要手动跑任何东西**——`SessionStart` hook 会在会话开始时自动对齐。
