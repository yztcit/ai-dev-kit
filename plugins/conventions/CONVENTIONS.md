# 工作约定

> **唯一事实源**；改约定只改这里。
>
> 交付方式（两种，同一份内容）：
> - **本机**：`~/.claude/rules/conventions.md` 软链到本文件 —— 原生用户级规则，启动时加载。
> - **分发**：`conventions` 插件的 `SessionStart` hook（plugin 无法交付规则，hook 是 plugin 内唯一可行方式）。

## 决策方式

- **技术取舍自主决策**：架构、方案、命名、迁移顺序、阈值等技术选择，**给结论并执行**，不逐个征求确认。仅业务取舍、风险接受度、成本预算且无法自行判断时才问。
- **需要方案时先取市面已验证的优秀实践**（行业做法、开源实现、官方文档、领域经验），再结合当前项目事实收敛。**不要请用户出方案，也不要让用户替你选**。
- **不要以「你要我先做哪个 / 需要你拍板」收尾**。暴露多个待处理项时，自行按「对目标的杠杆」排序、挑一条执行到底，其余留档即可。
- 决策要**留痕**（写进 CLAUDE.md / rules / 设计文档），否则后续会话不知道这些决策。

## 改动纪律

- **修问题从全局根因入手，不打补丁**：补丁 = 给特例加分支/豁免/阈值；结构 = 让这一类问题不再可能出现。
- **控制爆炸半径**：改一处不牵连多处。重构优先建隔离层、保持对外接口不变、每步可编译可回退、用 commit 隔断。
- 质量标准是**真实水准**，「凑合看」不算达标。

## 提交

- **提交前等用户明确确认**，不主动、不急着 commit。
- 提交信息**精简、侧重意图**（做了什么、为什么），不写流水账。
- **不加 `Co-Authored-By` 尾注。**

## 文档与知识的位置

- 计划/设计文档 → 项目内 `.claude/plans/`
- 项目共享知识（架构决策、团队上下文）→ 项目 `.claude/`，随 git 同步
- 个人习惯 / 本机环境 → auto memory
- 跨项目通用偏好 → 用户级 `CLAUDE.md` 或本插件

## 自动化优先

- 涉及防腐烂 / 巡检 / 健康评估类机制：**自动化产出「例外队列」，人只做低频裁决**，不做例行人工检查（人力检查必然漏和懒）。
- 保留人的**双向 override** 权：数据不理想但特殊场景可暂留；数据达标但人工判差可推翻。

## 协作方式

- 用户可能在**多个 AI 之间做交叉评审**（互换结论、互相反驳）。给其他 AI 的回复尽量**纯文本、可直接复制**（不要 markdown 表格 / 加粗 / 反引号）；把对方的反对意见当**真实输入**正面回应——同意就说清为什么，不同意就给反例与代价。
